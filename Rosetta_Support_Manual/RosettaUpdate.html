Purpose

Rosetta_Update.sh brings a machine up to date: the latest Rosetta files from GitHub, any new settings those files need, and the latest Debian, LinuxCNC and ClamAV packages. This machine's own settings and tuning are kept.

Updating Rosetta covers local changes, branches and going back to an earlier version; this page covers the program itself.

How it is run

  • The Update Rosetta desktop icon, and Applications > Rosetta > Update Rosetta. It runs in a terminal window.
  • From a terminal:

bash /home/reuben/linuxcnc/configs/Rosetta/Rosetta_Update.sh

Close LinuxCNC and Rosetta Settings first. It asks for the reuben password (for sudo). It needs the internet (Wi-Fi). Machines installed from the instructions get the files over HTTPS and need no GitHub login; a machine whose repository was switched to SSH (git remote -v shows git@github.com) also needs the reuben user's SSH key registered with GitHub.

Parameters

None.

What it does

  1. git stash - sets aside local changes to files in the repository (e.g. the tool table).
  2. git pull - gets the latest version of the branch the machine is on (normally main). If this fails, it puts the local changes back and stops.
  3. git stash pop - puts the local changes back. If the update changed the same lines, it leaves the files exactly as pulled, keeps the local changes in the stash, and prints a warning.
  4. Rosetta_Setup/Rosetta_Update_Settings.py - adds any new settings to this machine's settings file. A problem here is reported but the update carries on. It then:
    • runs the one-time steps for machines built before they were added to the installer - Rosetta_Add_Shortcuts.sh (folder shortcuts) and Rosetta_Set_Serial_Number.sh (asks for the serial number if none is recorded). Each does nothing once it has been done.
    • sends a version report (see below).
    • At the end, Rosetta_Setup/Rosetta_Renaming.py moves a machine still using the old Rose Engine Butler names over to the Rosetta names (it does nothing on a machine already moved).
  5. Refreshes the EtherLab package signing key - only if that package source is set up; a failure only warns.
  6. sudo apt update and sudo apt upgrade -y - stops with an error if either fails.

Programs it calls

Program What for
git (stash, pull, stash pop, reset) Getting the latest files from GitHub, keeping local edits.
Rosetta_Setup/Rosetta_Update_Settings.py Adds new settings to RosettaSet_v1.ini; uses Rosetta_Display/rosetta_settings_io.py.
Rosetta_Setup/Rosetta_Add_Shortcuts.sh, Rosetta_Set_Serial_Number.sh, Rosetta_Report_Version.py The one-time steps and the version report, run by Rosetta_Update_Settings.py.
curl, gpg, cmp, sudo install Fetching, checking and installing the EtherLab signing key.
sudo apt update, sudo apt upgrade -y Updating Debian, LinuxCNC, ClamAV and the other packages.

Files it reads

  • The whole repository at /home/reuben/linuxcnc/configs/Rosetta (through git)
  • Rosetta_Setup/RosettaSet_v1.ini - the shipped starting settings, with every setting
  • /home/reuben/Documents/RosettaSet_v1.ini - this machine's settings
  • /etc/apt/sources.list.d/ethercat.sources - the EtherLab package source, if present

Files it creates or changes

File Change
The repository files Replaced with the latest versions. Local edits are kept in a stash named Rosetta_Update date time when they can't be put back.
/home/reuben/Documents/RosettaSet_v1.ini New settings added with their starting values; Max Speed / Max Acceleration / PID Max Output filled in from this machine's own values if missing. Existing values are never changed, except:
- a stepgen speed or acceleration limit is raised if it is now below the axis's Max Speed / Max Acceleration;
- a spindle still on the old indexing PID (exactly P 2, I 1, D 1.2) gets I 0 and D 0 (since 08 November 2026 - the old values overshot and crept back);
- settings no longer used are removed: channel_types, signal_tower_active_low and the spindles' pid_vel (since 09 November 2026).
Missing file: created from the shipped copy.
/home/reuben/Documents/RosettaSet_v1.ini.bak-YYYYMMDD-HHMMSS A copy of the settings file from before the change - only when something was added, changed or removed.
Other /home/reuben/Documents/*.ini settings files The explanatory comment lines are added to saved and exported settings files that lack them. Their settings aren't changed.
The EtherLab keyring named in ethercat.sources Replaced, only if a newer copy of the same key is available.
/home/reuben/.config/Rosetta/report_log.jsonl One line added for every version report, whether or not it could be sent.
/home/reuben/.config/Rosetta/serial, the folder shortcuts Only the first time, on a machine that doesn't have them yet.
System packages Updated by apt.

Notes for support

  • It updates whichever branch the machine is on. Check with git branch --show-current - customer machines should be on main.
  • "git pull failed" - usually no internet. On a machine using SSH (git remote -v), GitHub may be asking for a passphrase or rejecting the key - test it with ssh -T git@github.com as reuben.
  • "local changes could not be re-applied" - see Updating Rosetta for finding them in the stash.
  • "settings file could not be checked" - RosettaSet_v1.ini couldn't be read. It is left as it was; check it isn't empty or hand-edited, and that reuben owns it (ls -l ~/Documents/RosettaSet_v1.ini).
  • EtherLab key warnings are harmless - nothing Rosetta uses comes from that source.
  • Version report. Every update sends this machine's Raspberry Pi hardware serial number, its serial number (if one was recorded), the Rosetta version and date shown on the panel, and the time, to https://rosetta.colvintools.com/Support/reb_report.php. Nothing else is sent. It is logged first in ~/.config/Rosetta/report_log.jsonl; if there's no internet it prints a warning and the update carries on (that report isn't sent later).
  • It asks for a serial number at every update until one is given (press Enter to skip). To set it later, run bash /home/reuben/linuxcnc/configs/Rosetta/Rosetta_Setup/Rosetta_Set_Serial_Number.sh.
  • Run it twice after a big change: the first run may update Rosetta_Update.sh or Rosetta_Update_Settings.py themselves, and the second run uses the new versions.
  • Once the update has run, start Rosetta normally - the new files take effect at the next launch.
  • The installer also puts a copy of this script at /home/reuben/Rosetta_Update.sh. Nothing uses it - the desktop icon and menu entry run the one in the Rosetta folder - and updates never refresh it, so don't run it.
