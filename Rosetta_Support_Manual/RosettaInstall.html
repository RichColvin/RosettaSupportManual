Note: ~ is the Linux shorthand for the home folder of whoever is logged in: /home/username. On a Rosetta that is /home/rosetta, or /home/reuben on machines built before November 2026, so commands written with ~ work on both. The terminal and the file manager's address bar understand ~; a few other places don't (G-code's LOGOPEN, for one) and need the full path.

Purpose

Rosetta_Setup/Rosetta_Install_Debian_13_Trixie.sh finishes setting up a new Raspberry Pi for Rosetta: the wired network, the Mesa card, the key files and the extra programs. It is one step of Installation and Setup for Debian 13 Trixie; it does not install LinuxCNC or download Rosetta - both must already be done.

REB_Install_Debian_12_Bookworm.sh is the older installer for Debian 12 (Bookworm) and isn't used for new machines.

How it is run

Once, on a new machine, from a terminal, as the Rosetta login (not with sudo - it asks for the password when needed):

cd ~/linuxcnc/configs/Rosetta/Rosetta_Setup
bash Rosetta_Install_Debian_13_Trixie.sh

Before starting: the repository is at ~/linuxcnc/configs/Rosetta, LinuxCNC is installed, the Pi has internet on Wi-Fi, and the base box's Mesa card is connected and powered with W5/W6 at the factory setting.

Parameters

None.

What it does

  1. Wired network - deletes any existing "Wired Ethernet" connections and creates one at 192.168.1.120, no gateway or DNS.
  2. Mesa card - copies 7i92t_Rosetta.bin, 7i92t_Rosetta.pin and PIN_Rosetta_34.vhd to /usr/lib/firmware/hm2/hostmot2, then runs Rosetta_Change_Network.sh base --no-shutdown (firmware, address 10.10.10.10, Pi moved to 10.10.10.100).
  3. Key files - .axisrc, a copy of Rosetta_Update.sh, the gcode folder and the starting RosettaSet_v1.ini (see below).
  4. ClamAV (virus scanner), with ~/ClamAv/SuspiciousFiles.
  5. MenuLibre (menu editor - for changing the menus further by hand).
  6. galculator (calculator).
  7. xfce4-screenshooter (screenshots).
  8. Claude Code - Node.js 20 from NodeSource, then the Claude Code npm package into ~/.npm-global.
  9. Chromium (web browser, from Debian's own packages).
  10. Folder shortcuts - runs Rosetta_Setup/Rosetta_Add_Shortcuts.sh: "Rosetta" and "Gcode" in the file manager's Places list, and two Turk's head launchers for those folders on the bottom panel, next to the File Manager.
  11. Serial number - runs Rosetta_Setup/Rosetta_Set_Serial_Number.sh, which asks for this machine's serial number (e.g. 4). Press Enter to skip; it is asked again at the next update. Then Rosetta_Setup/Rosetta_Set_Machine_Name.sh --install names the computer after it - rosetta-004 - without asking, so an owner's machines never share a name on the network (with no serial number, after the end of the Pi's own hardware serial, e.g. rosetta-9e4ddaf). It takes effect at the restart that ends the install.
  12. Rosetta menu and desktop icons - runs Rosetta_Setup/Rosetta_Add_Menu_And_Desktop.sh: the Applications > Rosetta submenu (Rosetta, Rosetta Settings, Back Up to USB, Update Rosetta), placed above Terminal Emulator; Rosetta and Rosetta Settings on the desktop, already trusted; Mail Reader, Games, Multimedia, Office and Science hidden. The submenu is named menulibre-rose-engine-butler in the menu file - the name the older, hand-made ones have - so the next steps find it on every machine. A machine that already has a Rosetta submenu is left as it is.
  13. Rosette Designer, Shut Down, Geometric Chuck Designer, User Manual and Gcode Library - Rosetta_Setup/Rosetta_Add_Rosette_Designer.sh, Rosetta_Add_Shut_Down.sh, Rosetta_Add_GeoChuck_Designer.sh and Rosetta_Add_Manuals.sh add each to the Rosetta submenu (Shut Down to the bottom of the Applications menu and the bottom panel; the manuals to the desktop too).
  14. Install check - runs Rosetta_Setup/Rosetta_Install_Check.py --before-jumpers, which checks everything above is in place (see Install check). If anything fails, the installer says so instead of "System successfully installed".
  15. Last step - asks to shut down, then: switch off, move the card's W5/W6 jumpers to EEPROM, switch on, and run Rosetta_Install_Check.py again - the full check, including the card.

Programs it calls

nmcli, Rosetta_Change_Network.sh (which uses mesaflash), cp, mkdir, sudo apt install, curl (NodeSource setup), npm, claude --version, Rosetta_Setup/Rosetta_Add_Shortcuts.sh (uses xfconf-query), Rosetta_Setup/Rosetta_Set_Serial_Number.sh, Rosetta_Setup/Rosetta_Set_Machine_Name.sh, Rosetta_Setup/Rosetta_Add_Menu_And_Desktop.sh, Rosetta_Add_Rosette_Designer.sh, Rosetta_Add_Shut_Down.sh, Rosetta_Add_GeoChuck_Designer.sh, Rosetta_Add_Manuals.sh (these use gio to mark desktop icons trusted), Rosetta_Setup/Rosetta_Install_Check.py, sudo poweroff.

Files it references

"Wired Ethernet" network connection Moved to 10.10.10.100 by Rosetta_Change_Network.sh.
/usr/lib/firmware/hm2/hostmot2/7i92t_Rosetta.*, PIN_Rosetta_34.vhd Copies of the card firmware and pin files.
~/.axisrc AXIS window size and position.
~/Rosetta_Update.sh A copy. Not used by the icons and never updated - ignore it.
~/linuxcnc/configs/Rosetta/gcode/ The operator's G-code folder.
~/Documents/RosettaSet_v1.ini This machine's settings, from the starting copy.
~/ClamAv/SuspiciousFiles/ Virus scan quarantine folder.
~/.npm-global/, a PATH line added to .bashrc Claude Code.
~/.config/gtk-3.0/bookmarks, two launchers on the bottom panel, ~/.config/Rosetta/shortcuts-added The folder shortcuts. The marker file stops them being added again - delete it, or run Rosetta_Add_Shortcuts.sh --force, to add them again.
~/.config/Rosetta/serial The serial number typed in (only if one was given).
/etc/hostname, /etc/hosts (the 127.0.1.1 line), /etc/cloud/cloud.cfg.d/99_rosetta_hostname.cfg The computer's name, rosetta- and the serial number. The cloud-init file stops Raspberry Pi OS setting the name back at boot. Until the restart, /etc/hosts lists the old name too; the next update tidies it.
~/.config/menus/xfce-applications.menu, ~/.local/share/applications/rosetta-*.desktop, ~/.local/share/desktop-directories/menulibre-rose-engine-butler.directory The Applications menu: the Rosetta submenu and its entries. Hidden menus are copies of their files in the same two folders with NoDisplay=true.
~/Desktop/rosetta-launch.desktop, rosetta-settings.desktop, rosetta-user-manual.desktop, rosetta-gcode-library.desktop The desktop icons.
~/.config/Rosetta/menu-and-desktop-added (and one marker per menu step) Stop each step being done again - run its script with --force to do it again.
~/Documents/Rosetta_Install_Check.txt The last install check's report.

Install check

Rosetta_Setup/Rosetta_Install_Check.py checks the install without changing anything (except its report, and the Rosetta.local files every start of Rosetta makes). It can be run at any time:

python3 ~/linuxcnc/configs/Rosetta/Rosetta_Setup/Rosetta_Install_Check.py

It checks: the Mesa card files, .axisrc, the gcode and ClamAV folders and the settings file; that LinuxCNC, mesaflash, ClamAV, MenuLibre, galculator, xfce4-screenshooter, Chromium and Claude Code are installed; the Wired Ethernet connection (10.10.10.100, no gateway) and that the base card - and the expansion card, if Expansion Box is ticked - answers; WiFi; the serial number and computer name; every entry in the Rosetta submenu, Shut Down and the hidden menus; the four desktop icons (each running something that exists, executable and trusted); the file manager's Places, the bottom-panel launchers and the one-time steps' markers; and that Rosetta.local.ini can be made.

Each line is OK, WARN or FAIL; it ends with a count, lists the failures again, and saves everything to ~/Documents/Rosetta_Install_Check.txt. It exits 1 if anything failed. With --before-jumpers (as the installer runs it), a card that doesn't answer is only a WARN. Run it from a terminal on the Pi's own screen - over SSH it can't tell whether the desktop icons are trusted (WARN).

Notes for support

  • Settings file ownership on older machines: installers before 24 October 2026 copied RosettaSet_v1.ini (and the home-folder Rosetta_Update.sh) with sudo, so on a machine installed before then they may have belonged to root. Rosetta now replaces the settings file each time it saves it, which gives it to the Rosetta login, so this normally fixes itself. If a save still fails, check the owner and fix it with:

ls -l ~/Documents/RosettaSet_v1.ini
sudo chown $USER:$USER ~/Documents/RosettaSet_v1.ini

  • Running it again is mostly safe: it replaces the "Wired Ethernet" connection (at 192.168.1.120 - run Rosetta_Change_Network.sh pi afterwards if the cards are already on 10.10.10.x), and overwrites RosettaSet_v1.ini with the starting settings - back it up first. "File exists" messages for folders are harmless.
  • A failed step stops the installer with "PROGRAM TERMINATED PREMATURELY". Read the message above it, fix the cause, and run it again.
  • Desktop and menu entries are made by the installer since 24 November 2026. Machines built before then had them made by hand with MenuLibre; their menus are left alone.
  • The expansion box's card is set up separately, with Rosetta_Change_Network.sh expansion.
  • Computer name: if the serial number was skipped, the computer is named after the Pi's hardware serial; once a serial number is set, the next update offers to rename it rosetta- and that number.
  • Folder shortcuts, menu entries, desktop icons or serial number missing: these steps are repeated by every update until they are done, so running Update Rosetta from the desktop fixes them. The shortcuts and desktop icons need the desktop to be running (they can't be added over ssh).
