Purpose

Rosetta_Setup/Rosetta_Install_Debian_13_Trixie.sh finishes setting up a new Raspberry Pi for Rosetta: the wired network, the Mesa card, the key files and the extra programs. It is one step of Installation and Setup for Debian 13 Trixie; it does not install LinuxCNC or download Rosetta - both must already be done.

REB_Install_Debian_12_Bookworm.sh is the older installer for Debian 12 (Bookworm) and isn't used for new machines.

How it is run

Once, on a new machine, from a terminal, as the reuben user (not with sudo - it asks for the password when needed):

cd /home/reuben/linuxcnc/configs/Rosetta/Rosetta_Setup
bash Rosetta_Install_Debian_13_Trixie.sh

Before starting: the repository is at /home/reuben/linuxcnc/configs/Rosetta, LinuxCNC is installed, the Pi has internet on Wi-Fi, and the base box's Mesa card is connected and powered with W5/W6 at the factory setting.

Parameters

None.

What it does

  1. Wired network - deletes any existing "Wired Ethernet" connections and creates one at 192.168.1.120, no gateway or DNS.
  2. Mesa card - copies 7i92t_Rosetta.bin, 7i92t_Rosetta.pin and PIN_Rosetta_34.vhd to /usr/lib/firmware/hm2/hostmot2, then runs Rosetta_Change_Network.sh base --no-shutdown (firmware, address 10.10.10.10, Pi moved to 10.10.10.100).
  3. Key files - .axisrc, a copy of Rosetta_Update.sh, the gcode folder and the starting RosettaSet_v1.ini (see below).
  4. ClamAV (virus scanner), with /home/reuben/ClamAv/SuspiciousFiles.
  5. MenuLibre (menu editor - used to add the desktop and menu entries).
  6. galculator (calculator).
  7. xfce4-screenshooter (screenshots).
  8. Claude Code - Node.js 20 from NodeSource, then the Claude Code npm package into ~/.npm-global.
  9. Chromium (web browser, from Debian's own packages).
  10. Folder shortcuts - runs Rosetta_Setup/Rosetta_Add_Shortcuts.sh: "Rosetta" and "Gcode" in the file manager's Places list, and two Turk's head launchers for those folders on the bottom panel, next to the File Manager.
  11. Serial number - runs Rosetta_Setup/Rosetta_Set_Serial_Number.sh, which asks for this machine's serial number (e.g. 4). Press Enter to skip; it is asked again at the next update.
  12. Last step - asks to shut down, then: switch off, move the card's W5/W6 jumpers to EEPROM, switch on, and run Rosetta_Change_Network.sh check.

Programs it calls

nmcli, Rosetta_Change_Network.sh (which uses mesaflash), cp, mkdir, sudo apt install, curl (NodeSource setup), npm, claude --version, Rosetta_Setup/Rosetta_Add_Shortcuts.sh (uses xfconf-query), Rosetta_Setup/Rosetta_Set_Serial_Number.sh, sudo poweroff.

Files it references

  • Rosetta_Setup/MesaCard/7i92t_Rosetta.bin, 7i92t_Rosetta.pin, PIN_Rosetta_34.vhd
  • Rosetta_Setup/axisrc
  • Rosetta_Update.sh
  • Rosetta_Setup/RosettaSet_v1.ini - the starting settings

Files and folders it creates

File or folder Notes
"Wired Ethernet" network connection Moved to 10.10.10.100 by Rosetta_Change_Network.sh.
/usr/lib/firmware/hm2/hostmot2/7i92t_Rosetta.*, PIN_Rosetta_34.vhd Copies of the card firmware and pin files.
/home/reuben/.axisrc AXIS window size and position.

/home/reuben/.config/Rosetta/serial The serial number typed in (only if one was given).

Notes for support

  • Settings file ownership on older machines: installers before 24 October 2026 copied RosettaSet_v1.ini (and the home-folder Rosetta_Update.sh) with sudo, so on a machine installed before then they may have belonged to root. Rosetta now replaces the settings file each time it saves it, which gives it to reuben, so this normally fixes itself. If a save still fails, check the owner and fix it with:

ls -l /home/reuben/Documents/RosettaSet_v1.ini
sudo chown reuben:reuben /home/reuben/Documents/RosettaSet_v1.ini

  • Running it again is mostly safe: it replaces the "Wired Ethernet" connection (at 192.168.1.120 - run Rosetta_Change_Network.sh pi afterwards if the cards are already on 10.10.10.x), and overwrites RosettaSet_v1.ini with the starting settings - back it up first. "File exists" messages for folders are harmless.
  • A failed step stops the installer with "PROGRAM TERMINATED PREMATURELY". Read the message above it, fix the cause, and run it again.
  • Desktop and menu entries aren't made by the installer - add them with MenuLibre (each icon's Command is the full path of the Rosetta_x.sh script it starts).
  • The expansion box's card is set up separately, with Rosetta_Change_Network.sh expansion.
  • Folder shortcuts or serial number missing: both steps are repeated by every update until they are done, so running Update Rosetta from the desktop fixes them. The shortcuts need the desktop to be running (they can't be added over ssh).
