Rosetta’s Key Programs: Overview · Rosetta_Launch.sh · Rosetta_Settings.sh · Rosetta_Backup.sh · Rosetta_Update.sh · Rosetta_Change_Network.sh · Rosetta_Install_Debian_13_Trixie.sh

The Rosetta_x.sh scripts are how the operator - and support - start every part of Rosetta. Each one is short; most of them only start a Python program, which does the real work. All of them live in ~/linuxcnc/configs/Rosetta (the installer is in its Rosetta_Setup folder).

Script Started from What it does Main program
Rosetta_Launch.sh Rosetta icon Builds this machine's configuration, then starts LinuxCNC. Rosetta_Generate_Local_Ini.py, linuxcnc
Rosetta_Settings.sh Rosetta Settings icon Changes this machine's setup and tuning (LinuxCNC closed). Its File menu also has Back Up to USB and Restore from USB. Rosetta_Settings.py
Rosetta_Backup.sh Backup Rosetta icon Copies settings, G-code, tool table and custom HAL to a USB stick. (Restore from USB, which copies a backup back, is in Rosetta Settings' File menu.) Rosetta_Backup.py
Rosetta_Update.sh Update Rosetta icon Latest files from GitHub, new settings, system updates. git, Rosetta_Update_Settings.py, apt
Rosetta_Change_Network.sh Terminal (support) Sets up the Mesa cards' addresses and the Pi's wired network; check shows which cards answer. mesaflash, nmcli
Rosetta_Install_Debian_13_Trixie.sh Terminal, once (new machine) Network, Mesa card, key files, extra programs, folder shortcuts and serial number. nmcli, Rosetta_Change_Network.sh, apt

Running any of them from a terminal

The desktop icons hide everything the programs print. When something doesn't work, run the same script in a terminal window and read the messages:

cd ~/linuxcnc/configs/Rosetta
./Rosetta_Launch.sh

"Permission denied" means the script isn't marked as runnable (a script can lose it when it is copied by hand): run it as bash ./Rosetta_Launch.sh, or restore the permission with chmod +x Rosetta_*.sh.

Rules they share

  • One at a time. Rosetta Settings, Restore from USB and the network script refuse to run while LinuxCNC is running; close LinuxCNC before an update too.
  • Settings live in one file: ~/Documents/RosettaSet_v1.ini. Rosetta Settings writes it, LinuxCNC saves live values into it at shutdown, the update adds new settings to it (and removes ones no longer used), Back Up to USB copies it, and Restore from USB puts a backed-up copy in its place. Rosetta_Launch.sh only reads it.
  • Changes apply at the next launch. Nothing changed in Rosetta Settings, by an update or by the network script reaches a running LinuxCNC.
  • Don't edit the scripts. An update replaces them, and changes to them aren't supported. Machine-specific HAL additions belong in Rosetta_Custom/Rosetta_Custom.hal, and AXIS window settings in ~/.axisrc.

Other programs support may meet

These are started by the scripts above or by LinuxCNC, not by the operator:

  • Rosetta_Setup/Rosetta_Generate_Local_Ini.py - builds Rosetta.local.ini and the .local HAL files at every launch (see Rosetta_Launch.sh).
  • Rosetta_Setup/Rosetta_Update_Settings.py - adds new settings, and removes ones no longer used, during an update (see Rosetta_Update.sh).
  • Rosetta_Setup/Rosetta_Renaming.py - at the end of every update, moves a machine still using the old Rose Engine Butler names over to the Rosetta names. Does nothing on a machine already moved.
  • Rosetta_Display/Rosetta_main.py - the AXIS side panel (Indexing, Sync Move, Threading).
  • Rosetta_Display/Rosetta_Axis_Commands.py - extra AXIS commands, loaded by AXIS as it starts (Rosetta.ini's [DISPLAY]USER_COMMAND_FILE). It runs ~/.axisrc, then adds the "not enabled" warning before Run (see Rosetta_Launch.sh).
  • Rosetta_Display/Rosetta_Settings_Restore.py - puts the saved scale, PID and limits onto the HAL pins as LinuxCNC starts.
  • Rosetta_Display/Rosetta_Scale_Persist.py - saves the live values to RosettaSet_v1.ini at shutdown (run by Rosetta_Shutdown.hal).
  • Rosetta_Display/rosetta_settings_io.py - shared code that reads and writes RosettaSet_v1.ini for all of the above.
  • Rosetta_Display/Rosetta_Backup.py - the Back Up to USB and Restore from USB windows (see Rosetta_Backup.sh).
  • Rosetta_Display/Rosetta_Program_Estimate.py - started by the side panel when a G-code program starts, to work out the progress bar's percentages.
  • Rosetta_Setup/Rosetta_Add_Shortcuts.sh - adds the Rosetta and Gcode folder shortcuts, once (installer, then updates).
  • Rosetta_Setup/Rosetta_Set_Serial_Number.sh - asks for and records this machine's serial number in ~/.config/Rosetta/serial (installer, then updates until one is given).
  • Rosetta_Setup/Rosetta_Report_Version.py - sends the version report at every update (see Rosetta_Update.sh).
  • Rosetta_Checkout.sh - bench checkout of a newly built system, with a test motor on every channel. Run from a terminal by whoever builds the machine.
