Purpose

Rosetta_Settings.sh starts Rosetta Settings, the window where this machine's setup is changed: which axis or spindle is on each channel, the expansion box, limit jacks, E-stop button, signal tower, sounds, scale, speed limits, backlash, PID tuning, jog speeds, measurement system and device names.

Everything it changes is stored in /home/reuben/Documents/RosettaSet_v1.ini and takes effect the next time Rosetta is started. How to use each page is in the User Manual (web site); this page covers what support needs to know.

How it is run

  • The Rosetta Settings (gear) desktop icon, and Applications > Rosetta.
  • From a terminal, which also shows its messages:

/home/reuben/linuxcnc/configs/Rosetta/Rosetta_Settings.sh

LinuxCNC must be closed first. If it's running, Rosetta Settings shows "LinuxCNC is currently running" and closes.

Parameters

None.

File menu

  • Save All Settings (Ctrl+S), Save All Settings As... (Shift+Ctrl+S), Save Subset of Settings As..., Load Settings from File... (Ctrl+O) - the same as the four buttons on the Axis Selection tab.
  • Back Up to USB... - opens the same window as the Back Up to USB icon.
  • Restore from USB... - copies a backup from a USB stick back onto the Raspberry Pi (see Rosetta_Backup.sh), then closes Rosetta Settings.
  • Quit (Ctrl+Q) - asks about unsaved tuning changes.

Programs it calls

Program What for
Rosetta_Display/Rosetta_Settings.py The program itself (Python 3, GTK 3). Uses Rosetta_Display/rosetta_settings_io.py to read and write the settings file.
halcmd Reads and sets live HAL values. Since LinuxCNC isn't running while Rosetta Settings is open, these calls normally find nothing; "halcmd not found" or "pin not found" messages in the terminal are harmless.
The web browser The User Manual buttons open the matching User Manual page.
Rosetta_Display/Rosetta_Backup.py The File menu's Back Up to USB and Restore from USB windows.

Files it reads

  • Rosetta_Display/Rosetta_Settings_v1.ui - the window layout
  • /home/reuben/Documents/RosettaSet_v1.ini - this machine's settings
  • Any settings file chosen with Load Settings (normally in /home/reuben/Documents)

Files it creates or changes

File When
/home/reuben/Documents/RosettaSet_v1.ini As soon as they change: channel assignments, expansion box, limit jacks and switch type, E-stop button, signal tower, sounds, startup file check, backlash, jog speeds, measurement system, device names.
Only on Save All Settings: scale, Max Speed, Max Acceleration, stepgen limits, PID values. Closing the window with unsaved tuning asks Save and Close / Close Without Saving / Cancel.
A file name chosen by the operator, normally in /home/reuben/Documents Save All Settings As... (a full copy) and Save Subset (an export of chosen settings, to bring into another machine).
Files restored by Restore from USB See Rosetta_Backup.sh.

RosettaSet_v1.ini is JSON with comment lines at the top and bottom, despite its .ini name. Don't edit it by hand - use Rosetta Settings, or Load Settings from a saved copy.

Notes for support

  • A change "didn't work": changes apply at the next launch of Rosetta, not straight away. Ask whether LinuxCNC was restarted.
  • Tuning changes lost: scale, speed limits and PID values are only kept after Save All Settings (Ctrl+S).
  • Duplicate! / Conflict! warnings (red) mean that change has not been saved - two channels have the same role, Sp1 is assigned without Sp0, or two limit jacks clash. Fix the warning and the setting saves.
  • Orange "not assigned - cleared" next to a limit jack means its axis lost its channel, so the jack was set to Not used.
  • Expansion Box - Connected needs the 10.10.10.x network - see Rosetta_Change_Network.sh.
  • LinuxCNC also saves the live scale and other values into RosettaSet_v1.ini when it shuts down, so values tuned in a running session end up in the file too.
  • Startup File Check (Other tab) decides what happens when the gcode folder holds a reserved file name - see Rosetta_Launch.sh. Leave it at Abort startup - recommended.
  • Before trying a different set of settings, take a copy with Save All Settings As... - it can be loaded back with Load Settings.
  • Rosetta Settings closed by itself after Restore from USB - that is deliberate, so it can't save the settings it was showing over the restored ones. Open it again to see the restored settings.
