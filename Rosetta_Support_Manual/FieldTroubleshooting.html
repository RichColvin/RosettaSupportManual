Field Troubleshooting

On this page

First, collect this

  1. The software version:

cd /home/reuben/linuxcnc/configs/Rosetta
git log -1 --oneline
git status

  1. The generator's output (what LinuxCNC will load):

cd /home/reuben/linuxcnc/configs/Rosetta
python3 Rosetta_Setup/Rosetta_Generate_Local_Ini.py

  1. The network check (which cards answer, and the Raspberry Pi's wired address):

bash /home/reuben/linuxcnc/configs/Rosetta/Rosetta_Change_Network.sh check

  1. A copy of /home/reuben/Documents/RosettaSet_v1.ini.
  2. Whether the machine has an expansion box, and whether Expansion Box - Connected is ticked in the Settings program (Axis Selection tab).
  3. If LinuxCNC starts: the HAL state, from a terminal while it is running:

halcmd show all > ~/all.txt

  1. Any error text from starting LinuxCNC in diagnostic mode (see Diagnostics).
  2. The machine's serial number and version: the Rosetta O/S label on the side panel gives the version and date, and the serial number (if one was recorded) is in ~/.config/Rosetta/serial:

cat ~/.config/Rosetta/serial
tail -n 1 ~/.config/Rosetta/report_log.jsonl

The last line of report_log.jsonl is the most recent version report (sent at each update).

LinuxCNC won't start

  • Run the generator by hand (above). If it reports a problem, it refuses to write the configuration.
  • "Reserved file name found - startup stopped" - a file in the gcode folder starts with Rosetta or is named M100 - M199. Rename it - see Rosetta_Launch.sh.
  • Check the Mesa cards are reachable: run the network check above, or ping 10.10.10.10 (base card) and ping 10.10.10.11 (expansion card), then read a card with mesaflash --device 7i92t --addr 10.10.10.10 --readhmid (see Mesa 7i92).
  • The Raspberry Pi's wired address should be 10.10.10.100 (ip -4 addr show eth0). If it isn't, run Rosetta_Change_Network.sh pi.
  • A machine not yet moved to the 10.10.10.x network (Raspberry Pi on 192.168.1.120, card at its factory 192.168.1.121) still runs the base box, but the generator refuses to start with Expansion Box - Connected ticked. Move it with Rosetta_Change_Network.sh (see Installation and Setup for Debian 13 Trixie, Part 3), or untick the expansion box.
  • Expansion Box - Connected is ticked but the expansion box is off or unplugged: switch it on and plug it into the switch in the base box, or untick it.
  • A card that doesn't answer at its 10.10.10.x address: check its cable to the switch, its power, and that its W6 jumper is up (W5 down). Jumpers are read only at power-up.
  • Nothing else may be plugged into the switch in the base box - no router or other computers.
  • Look for hm2 / gpio / num_inms errors in the diagnostic output.
  • The Raspberry Pi restarted by itself when the machine (or a box) was switched on: the Pi and the base card share one 5V supply - always switch the whole machine off and on together. Afterwards run Rosetta_Change_Network.sh check.

"Base box lost contact" or "Expansion box lost contact"

If either Mesa card stops answering while LinuxCNC runs (a network cable, the switch, or a box's power), LinuxCNC drops into E-stop, lights the signal tower's red light and sounds the fault siren (if used), and shows which box it was. (If it was the base box, the tower stays dark - its outputs are on the base card.) Check that box's network cable, the switch and its power, then press F1. While in E-stop, Rosetta tries to reconnect the card every few seconds; F1 resets the E-stop once the card answers again.

"Unexpected realtime delay"

LinuxCNC's 1 ms servo thread overran. With two cards each cycle waits for both, so there is less spare time than with one.

  • Close the web browser and other busy programs while Rosetta runs - a busy browser can take two of the Raspberry Pi's four cores.
  • Make sure nothing but the Raspberry Pi and the Mesa cards is on the switch.
  • Watch the servo thread's worst time with halcmd show thread (the servo-thread Max Time, in ns). It should stay well under 1,000,000.
  • If it keeps happening, the next step is reserving a processor core for LinuxCNC (isolcpus) - ask for support.

An axis doesn't move

  • Is it assigned to a channel, and is the motor on the plug for that channel? See Axis Mapping and the generator output.
  • Is that channel on the expansion box (06 - 09)? Then Expansion Box - Connected must be ticked, or the role is left out.
  • On an earlier 8-channel box, channels 06 and 07 now belong to the expansion box; move a role on them to a base channel (00 - 05).
  • Is its ENA on (green) on the main panel, and the machine powered on (F2)?
  • Is the DM542T's 5V/24V switch set to 5V? At 24V (as new drivers come) the driver doesn't respond to the Mesa card.
  • Is its Scale plausible? A value off by 1000x moves too little to see.

Limit switch, E-stop, or signal tower misbehaving

See Panel Accessories. Limit Jacks 4 - 6 (on the expansion box) only work while the expansion box is connected and ticked.

The customer's tool table or custom HAL changes disappeared after an update

Update Rosetta sets local changes to tracked files (such as Rosetta_Custom/Rosetta_Tool.tbl and Rosetta_Custom/Rosetta_Custom.hal) aside before pulling and puts them back afterwards. If the update changed the same lines, or the machine was updated before 30 September 2026 (when the update didn't put them back), they are still in the stash - see Updating Rosetta.

Going back to the previous version

See Updating Rosetta. A machine already moved to the 10.10.10.x network needs its network put back before it runs a version from before the two-box design.
